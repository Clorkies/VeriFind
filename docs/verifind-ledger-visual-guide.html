Verifind: Architecture & Flow

A visual guide to the system's implementation status, user flow, and technical headless Cardano ledger integration.

1. Implementation Status Audit

Core Pillars Established

  • Institutional Verification: Replaced wallet addresses with Student IDs and added a "Staff Secret" field to prevent fraudulent claims.
  • Persistent Backend: Migrated all data to Supabase (PostgreSQL), replacing the mock JSON files.
  • Real-time Sync: The board and admin panel update instantly using Supabase's replication features.
  • On-Chain Audit Trail: Critical events are anchored to the Cardano Preprod network via server-side signing.

Minor Gaps for Future Iterations

  • Admin Auth: The panel at /admin is currently open to anyone; integrating NextAuth with Supabase is the next step for production security.
  • Photo Storage: Photo URLs are currently text strings; integrating Supabase Storage would allow for direct image uploads.

2. Testing Guide & Recommended Flow

1

Admin Intake Admin Role

Action: Go to /admin and log a new item (e.g., "Silver Watch").

Crucial: Add a "Secret" that only the owner knows (e.g., "Engraved with 'To John' on the back").

Verify: The item appears on the /board instantly.

2

Student Discovery & Claim Student Role

Action: Open /board in a new window. Click "View Details" on the Watch.

Action: Fill out the claim form with a Student ID (e.g. 20-1234) and describe the secret: "It has an engraving on the back that says 'To John'".

Verify: The claim appears in the "My Claims" section for that Student ID.

3

Admin Review & Approval Admin Role

Action: Go back to /admin. In the Claim Queue, compare the student's proof to the hidden secret.

Action: Click Approve.

Verify: The item status on the board changes to "Under Review".

4

Pickup & Final Release Ledger Event

Action: Once the student arrives at the desk, the admin clicks "Release Item".

Verify: The item status changes to "Returned". Click the "On-chain ↗" link on the item card to see the final audit record on the blockchain.

3. Cardano & Ledger Technical Overview

The system uses a Headless Anchoring model in /api/ledger/anchor/route.ts to provide transparency without requiring students to use blockchain tools. Transactions pay the admin wallet back to itself, managing UTxOs easily while attaching metadata (CIP-674).

1. Transaction Building & Metadata

Every event (Item Logged, Claim Approved, Item Returned) is attached as a JSON payload to the transaction metadata (Label 674).

app/api/ledger/anchor/route.ts 
const metadata = {
  app: "verifind",
  event: body.event,
  itemId: body.itemId,
  claimId: body.claimId ?? null,
  adminId: body.adminId,
  timestamp: new Date().toISOString(),
};

const tx = new Transaction({
  initiator: wallet as any,
  fetcher: provider,
  submitter: provider,
  evaluator: provider,
  verbose: false,
})
  .sendLovelace(changeAddress, "2000000")
  .setMetadata(METADATA_LABEL, metadata);

const unsignedTx = await tx.build();

2. Signing the Transaction

The transaction is signed server-side by the MeshCardanoHeadlessWallet using the environment's CARDANO_ADMIN_MNEMONIC.

app/api/ledger/anchor/route.ts 
// Wallet instantiated from mnemonic previously
const signedTx = await wallet.signTxReturnFullTx(unsignedTx);

3. Submitting to the Network

The signed transaction is submitted to the Cardano network (via Blockfrost provider).

app/api/ledger/anchor/route.ts 
const txHash = await provider.submitTx(signedTx);
return Response.json({ txHash });

4. Transparency & Status Audit

The resulting txHash is saved to Supabase and exposed via the UI. Users can click the anchor link on an Item Card to verify the on-chain metadata via Cardanoscan.

app/components/ItemCard.tsx 
const short = truncateTxId(item.txHash);

  ? `https://preprod.cardanoscan.io/transaction/${item.txHash}`
